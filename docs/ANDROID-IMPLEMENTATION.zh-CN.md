# Android Alpha 实现审查记录

对应 PR #5、Issue #2。初始代码提交 `3194c6530ace90bc2dfc5dc5f2926de1ec1e61da`。后续修复和当前测试结论查对应 Actions，不把本文件当作永久最新结果。

## 交付边界

本轮写入固定点控制端、独立系统 Probe、事务模型及 23 项 JVM 测试、SDK 36 构建和 Lint、debug APK 工件、构建元数据与中文安装恢复说明。构建检查不等于安装/启动/微信行为检查。没有接触用户手机或 Mac。

## 审查要点

- 操作定位源前同步写清理意图；中途失败逐项清理；清理确认失败保留记录。
- 所有写入序列限制在服务主线程；禁止同实例活动会话被另一个开始请求替换。
- elapsedRealtimeNanos 严格递增；墙钟回拨本身不否定单调时间，但非正值拒绝。
- 原生 API 返回成功只标记下发；Probe 拥有独立进程、权限和缓存，不共享控制端代码。
- 只有本轮订阅后产生且年龄不超过 10 秒的读数才标为新鲜；无新回调保持等待。
- 清理后只显示等待恢复；Probe 的非模拟标记/基线距离只作为观察事实，不自动给真实定位或微信打勾。
- 无 BootReceiver、START_STICKY、网络权限、定位标志掩盖或微信修改。
- Provider 归属不能通过公开 API 完全证明；恢复前停止竞争工具并由用户确认。强停不保证执行 onDestroy。
- 控制服务持有带时间上限的唤醒锁；设备省电、锁屏和耗电仍需实测。
