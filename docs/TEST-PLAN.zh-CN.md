# 真机验收规程

当前无真机测试完成。自动化构建、模拟器和上游声明不得填入通过记录。

## 准备

使用自有设备和知情的测试账号。先记录不模拟时的权限、定位行为与可信基线；设备型号、OS 完整构建、微信构建/安装渠道、工具提交和后端版本必须齐全。原始精确位置和设备标识留在受控本地，不传公共仓库。

S25 与 iPhone 轮流作为模拟端；另一台保持真实定位作为接收端。不要同时模拟再把相同蓝点当作双方验证。

## 每轮步骤

1. 独立系统 Probe 采集基线，确认时间与坐标系。
2. 在控制端明确开始固定点。记录后端回执，不将其当作系统证据。
3. 独立 Probe 读取新鲜结果并比较目标。GCJ-02 与 WGS-84 先校准边界。
4. 微信逐项进入发送位置、实时共享、朋友圈、小程序、网页及可见附近入口；观察接收端和原始接口结果。
5. 先暂停确认保持点，再停止并记录清理回执，最后独立检查恢复。任何未知状态保留，不靠重启界面清除失败记录。

## 场景矩阵

不模拟基线；附近固定点；跨城固定点；多段路线与停留；控制端后台/微信前台；锁屏解锁；Wi-Fi/蜂窝切换；拔线；桌面休眠；应用强停；权限撤销；配对失效；正常停止；重启后的不自动模拟。

目标测试量：实时共享 30 分钟，其中锁屏 10 分钟；启停至少 20 次。每个模式独立统计。无接口权限标 blocked，入口不存在标 not_applicable；不能把跳过步骤记通过。

受控固定点原始坐标链路目标误差不超过 10 米；只有地图图像时使用比例尺作粗粒度结论。系统信号恢复不设必然成功的秒数承诺。耗电/发热与同设备同环境基线比较。

## 报告

复制 compatibility 中对应模板到被忽略的 reports/local 目录，按 schemas/report.schema.json 填写。证据 ID 指向你受控保存的脱敏记录；不包含文件路径、分享 token、配对材料或聊天内容。公共提交仅放审阅后的脱敏结论。

报告校验只检查一致性，无法替代观察者。保留失败证据，禁止修改测试预期来让结果通过。
